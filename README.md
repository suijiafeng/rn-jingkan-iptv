## 功能

### 节目源

- 通过 HTTP(S) 链接或系统文件导入 M3U/TXT；按实际字节限制 8 MiB，支持 UTF-8/GBK，先预览统计再确认保存
- 已用 iptv-org 完整列表（11,344 个频道）实测导入
- SQLite 事务刷新，频道身份稳定；消失的收藏保留为失效条目，旧任务不能覆盖新数据或复活已删除来源
- 来源可改名、刷新、删除（删除前显示名称确认）
- 手动“检测可用性”：每个地址先请求前 1 KiB（服务器以 416 拒绝 Range 时改为不带 Range 再请求一次），单次请求 8 秒超时、4 个并发，可随时停止。HLS 节目单会继续检查第一个子节目单和第一个分片，单个频道最多 4 次请求、总计 15 秒；节目单为空或分片指向私网等不安全地址时只检查到节目单为止。连接失败、超时或临时状态（408、429、5xx）会在 1 秒后整体重试一次，其他 HTTP 错误不重试；结果只说明各步服务器有响应，不代表能解码。来源管理显示本次检测的结果；没有本次结果时显示 SQLite 中保存的上次检测时间与可访问、不可达数量（含实际播放更新的结果），重启应用后仍保留

### 浏览

- 来源选择，国家/地区、语言、内容下拉筛选，中文名称搜索；筛选栏吸顶
- 分组按“;”拆分并译成中文，`[Geo-blocked]` 等标记显示为标签
- 独立收藏按钮，最近成功播放的 100 个频道

### 播放

- expo-video 原生播放器，暂停/重连直播，上一台/下一台，底部选台面板
- 横屏沉浸全屏（隐藏状态栏与导航栏），轻触显隐控件，播放 4 秒后自动隐藏；TalkBack 开启时不自动隐藏
- 全屏上下滑动换台（方向可反转），台名浮层，等待计时与慢源提示，可跳过检测为不可达的频道
- 超时或可分类的错误会尝试同频道备用源；未知原生错误只提供手动重试
- 已经开始播放的直播如果中途报“源错误”（通常是播放进度落后于直播窗口，或服务器不再更新节目单），会在同一地址重新连接到最新位置；每 2 分钟最多 3 次，超过后才显示错误。已经播放过的地址不会因此被标为不可达
- 手动画中画（需系统允许）；后台播放与系统媒体控制，默认开启，可在设置中关闭
- 直播长暂停后安全重连

### 资料与外观

- 设置中手动导出/恢复节目源、收藏和播放偏好：上限 32 MiB，有格式校验，失败事务回滚
- 清理观看记录或全部资料
- 深色薄荷绿界面，48 dp 触控目标，专属图标与深色启动画面；关于页显示版本与构建号、隐私与权限说明

**不提供**：内置频道、自动下载列表、版权破解、付费节目授权、录制、EPG、投屏和电视端。

## 播放器界面

控件位置固定，切换状态不会让按钮跳动。

**竖屏**

```
┌──────────────────────────────┐
│ ‹                          ⧉ │  关闭播放器（停止播放）/ 画中画
│                              │
│         ⏮    ▶    ⏭          │  上一台 / 播放·暂停 / 下一台
│                              │
│ 00:12 ━━━━━━━━━━━━━━   🔊  ⛶ │  进度 / 静音 / 横屏全屏
└──────────────────────────────┘
```

**横屏全屏**

```
┌──────────────────────────────────────────────────────┐
│ ‹  CCTV-1                     [1080p · 我的节目单]  ☆ │  退出全屏 / 台名 / 来源 / 收藏
│    第 1 / 11 台 · 正在播放                             │
│                                                      │
│                  ⏮     ❚❚     ⏭                      │
│                                                      │
│ 直播                                     🔊   ⤡   ☰ │  静音 / 退出横屏 / 频道列表
└──────────────────────────────────────────────────────┘
```

- **中央三键**：在连接中、失败、暂停、播放等所有状态下都固定在画面正中；状态说明显示在按钮上方，文字只向上延伸。中间的按钮随状态变化：连接中为 ■（取消），失败后为 ↻（重试），停止或暂停时为 ▶，播放中为 ❚❚。
- **右侧按钮组**：音量和来源分别排在各自那一组的第一个。
- **来源**：横屏时在右上角，点开后列表从右上角弹出；点列表以外的地方或再点一次按钮即可收起。竖屏时从底部面板打开。
- **静音**：只切换本应用的静音，不改变系统音量；竖屏、全屏和小窗共用同一状态。换台、换来源或重试不会解除静音，关闭播放器后重置。
- **画中画**：只在竖屏右上角提供。
- **返回键**：依次关闭来源列表或频道面板、退出全屏、返回原列表。

**后台播放**默认开启。切换应用或锁屏会继续播放，系统媒体控件可以暂停或恢复；关闭时切到后台就停止播放，正在画中画时除外。后台播放会持续消耗流量和电量，系统强制结束进程后不保证继续。备份不包含这个开关，恢复后回到默认的开启状态。

## 第一次使用

1. 打开“添加节目单”，粘贴你信任且有权访问的 M3U 地址，或选择本地文件。
2. 首次联网前阅读并明确同意风险说明；拒绝时不会联网读取或播放。
3. 查看有效、重复、忽略的条目，确认保存后再选频道播放。
4. 收藏常看的频道；在设置中管理来源、撤销联网许可。

[`fixtures/example.m3u`](fixtures/example.m3u) 只是结构测试夹具，其中的 example.com 地址是占位符，不能播放。测试报告里出现的真实 URL 不会预置进应用。

## 隐私与网络边界

- **没有遥测**：不打印来源令牌，不上传观看记录；Android `allowBackup=false`，并通过 `dataExtractionRules` 排除云备份与设备间迁移（含 Android 12+ 的 Smart Switch），仍需真机确认。
- **联网许可不等于 HTTPS-only**：平台允许 HTTP。HTTPS 主链接仍可能引用明文子清单、分片、密钥或重定向；expo-video 的原生 HLS 请求不经过 JS，本应用不声称能阻断所有 DNS、重定向或内网请求。只使用可信来源。TLS 证书校验没有关闭。
- **撤销许可**会取消本应用的导入并释放播放实例；原生请求实际停止的时序仍需真机确认。
- **移动数据**：VPN 和未知网络都按可能计费处理；确认一次后直到连回 Wi-Fi 前不再询问。
- **可用性检测**由全局队列调度，按完整地址去重，结果存在 SQLite 中并在各处共用；可访问结果复用 24 小时、不可达结果复用 6 小时，过期后自动或手动检测时重新请求，“重新检测”立即强制刷新。只命中缓存时不联网；真正检测前仍需联网许可和流量确认。实际起播成功、连接超时及明确的地址或媒体错误也会更新同一份结果；暂停、断网、许可拦截和未知原生错误不标记为不可用。“可访问”只说明主地址返回成功，不代表能解码或持续播放。
- **台标**默认关闭；单独授权后才显示经过校验的 HTTPS 台标，缺图时显示频道名首字；带英文前缀的频道显示台号或前缀后的首字（如 CCTV5 显示“5”、CGTN法语显示“法”）。
- **国家/地区**：默认参考手机地区、语言和时区；IP 查询（ipapi.co）和前台单次定位须分别在应用内授权，没有后台定位。手动选择（含“全部”）始终优先；证据冲突或节目单没有相应标注时回退为全部。国家/地区和语言只取节目单明确提供的属性，不从频道名或地址猜测，旧资料需手动刷新才能补充。
- **备份文件未加密**，含地址与令牌；不包含观看记录，也不包含联网、台标和地区识别许可。

## 打包 APK

需要已接受条款的 Android SDK、JDK 21 和上表中的 SDK/NDK 版本（可用 Android Studio 的 SDK Manager 准备），并设置 `ANDROID_HOME` 与 `PATH`。

**本地测试包**

```sh
npm ci
npm run release:test
```

生成独立的 `release/` 目录，包含 APK、校验和、证书、构建记录和开源许可。APK 内含 JS bundle，不依赖 Metro。未配置正式密钥时使用 Debug 签名。

开发调试可用 `npm run android`（需连接设备或模拟器，通常依赖 Metro）。`assembleDebug` 的产物不能当作独立安装包。

**正式包**

release keystore 由你自己保管，密钥和密码不要发到聊天或提交到 Git。更换签名后无法原位升级，卸载会清空本地资料。

```sh
./scripts/create-release-keystore.sh   # 交互输入密码；写入 ~/.jingkan 与 ~/.gradle/gradle.properties
npm run release:check
npm run release:build
```

正式打包入口会强制检查密钥、工作区是否干净、最终 APK 签名和权限。直接构建 release 时如果缺少密钥，会改用 debug 密钥签名并在日志中警告；加 `-PjingkanRequireReleaseKey=true` 则直接失败。请备份 keystore 和密码。
