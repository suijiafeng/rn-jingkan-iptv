> v0.2 相对 v0.1 的变更：根据实现（工程「静看」jingkan-iptv）与代码审查结果，采纳 HTTP 加应用内知情许可、备份与换机迁移排除、沉浸式全屏与轻触显隐控件、移动网络统一判定、2 MiB 导入上限、批量写库等决定；变更点在正文以「v0.2」标出，并在第 13 章汇总。
## 项目结论
先做一个能在三星 Galaxy S25 Ultra 上安装、导入节目源并直接播放的React Native 安卓应用。采用 TypeScript、Expo development build 和 expo-video，所有频道、收藏和设置保存在本机。v0.2 冻结版本：Expo SDK 58.0.14、React Native 0.88.0、React 19.3.0、expo-video 58.0.11、expo-sqlite 58.0.13、TypeScript 6.0.3、Node 24.19.0；原生生成配置 compileSdk 37、targetSdk 36、minSdk 24，构建需 JDK 21。第一版不建设服务器，不做账号体系，不接广告或统计 SDK。
本文件是可交给开发者或 AI 编程工具执行的开发规格，包含页面、数据模型、播放状态、安全边界、任务拆分和验收标准。它定义的是待实现的版本，不表示 APK 已完成，也不表示下列性能目标已经实测。
首要目标是自己每天使用舒服：打开快，常看频道容易找到，换台和全屏顺手，出错能看懂。先用真实日常观看反馈打磨，再决定是否推广；推广不是当前阶段的交付要求。
## 第一版交付目标
用户安装 APK 后，可以添加一个 M3U 链接或选择本地 M3U 文件，按分组浏览、搜索、收藏频道，点选播放，并在竖屏和横屏全屏之间切换。播放失败时应告诉用户属于哪类问题，并提供有边界的重试。
“无广告”指应用不展示启动广告、横幅、插屏、激励广告，也不集成广告 SDK。直播源已经混入的视频广告仍会播放；第一版不做广告识别、剪除或绕过。
## 设备和待确认事项
主验收设备已确定为三星 Galaxy S25 Ultra。开发开始前记录手机当前 Android 版本、One UI 版本、可用存储和常用网络；不能仅根据机型猜测已安装的系统版本。
最低 Android 版本由选定稳定 Expo SDK 和其配套 React Native 版本决定，实施时核对官方兼容范围。Node、包管理器、JDK、Gradle、compileSdk 和 targetSdk 一起冻结，不独立猜测最低系统或追逐最新版本。S25 Ultra 当前系统仍需记录，不能宣称所有安卓设备兼容。

# 1 产品范围和用户流程

## 必须实现
P0：M3U URL 导入、本地文件导入、导入结果统计；频道列表、分组筛选和名称搜索；点击播放、暂停、全屏、旋转适配、错误提示和手动重试；本地持久化及来源删除确认。
P1：收藏、最近观看、手动刷新来源、清理观看记录、深色主题、移动网络提醒。P0 与 P1 都属于本次 v0.1 交付，但先完成 P0 的纵向闭环，再补 P1。
## 明确不做
电视端、遥控器焦点导航、投屏、EPG 节目单、回看、录制、下载、画中画、后台音频、会员登录、订阅支付、云同步、后台定时刷新和频道服务器均延期。DRM 授权、付费平台登录、特殊请求头和来源内脚本不在第一版兼容承诺内。
不能通过转发服务器解决来源失效；手机直接访问来源。后续电视版复用领域模型、导入规则和播放器接口，重新设计大屏交互，不把手机页面直接拉伸当电视版。
## 首次使用流程
首次启动进入空频道页 → 点击“添加来源” → 选择链接或文件 → 显示来源权限与网络提醒 → 读取并预览导入统计 → 用户确认保存 → 展示频道 → 点击频道开始播放。导入成功不等于每个频道可播放，也不在导入阶段逐个探测所有频道。
## 日常观看流程
从频道、收藏或最近观看进入播放器。进入播放器只允许一个活跃播放会话；选择新频道时取消旧频道的准备、重试和网络请求。返回列表恢复原筛选和滚动位置，停止本次播放；再次进入从直播当前位置开始。
## 日常交互优先级
收藏和最近在底部一键可达；日常启动有收藏则进入收藏，否则进入频道，不自动播放。S25 Ultra 大屏上的播放、换台、重试和返回尽量放在单手易触达区域。播放器底部提供“上一台”“下一台”和“频道”按钮；频道按钮打开底部面板，保留当前筛选并可切换收藏，突出当前频道。选台后自动收起面板、保持全屏状态；上下台按当前列表顺序，边界禁用，不暗中循环。
所有页面遵循统一反馈：触碰即有响应，耗时操作显示进度或状态并防止重复提交；空页面给下一步，失败给原因与恢复动作。导入失败保留名称和地址输入，取消导入返回后不丢已有频道；离开未提交表单先询问是否放弃。底部导航返回既有页面位置，键盘关闭后恢复合理焦点。
## 更新和删除流程
来源管理中点击刷新，保持旧频道可用，直到新列表完整验证并提交。刷新失败保留旧数据和收藏。删除来源时显示来源名称、频道数及关联收藏影响，确认后停止该来源播放、取消其任务并清理关联数据。
## 节目源与版权
应用只读取用户有权使用的节目源，不提供付费频道破解。公开目录可以作为研究入口，但公开可访问不等于获得观看、再分发或商业使用授权；地区限制、令牌到期和运营方策略也会影响可用性。
iptv-org 中文列表可作为用户主动选择的示例来源，不默认后台下载或保证频道长期有效。测试优先使用开发者自建且有权使用的固定素材，公网频道只做补充测试。

# 2 页面入口和界面状态

## 主导航
底部导航为“频道”“收藏”“最近”“设置”。频道页顶部提供来源选择、分组筛选、搜索框和添加入口；来源管理由设置进入，空列表也可直接进入添加来源。所有页面保留明确返回路径，不把错误弹窗当成唯一反馈。
## 频道页
入口：启动、底部导航、导入完成。显示来源名称、分组、频道名称和收藏按钮。状态包括加载、无来源、来源有但无频道、无搜索结果、正常列表、刷新中和刷新失败。无来源提供添加按钮；无搜索结果提供清空条件；刷新失败仍展示旧列表。
搜索仅匹配本地频道名称，忽略首尾空格和英文大小写；支持中文子串。默认范围为当前来源和当前分组，界面显示范围，避免用户误认为全库搜索。搜索输入延迟约 250 毫秒触发，新的查询取消旧查询。
v0.2 分组与标记：group-title 按“;”拆成多个分组并把 iptv-org 英文分类译成中文（如 Culture;Documentary → 文化、纪录片），Undefined 归入“未分组”；分组按钮按拼音排序、“未分组”最后，一个频道可出现在多个分组下。频道名末尾的 [Geo-blocked]、[Not 24/7] 等方括号标记在列表中显示为“地区限制”“非全天”标签，存储与搜索仍用原名。手动检测为不可达的频道显示“上次检测不可达”标签，并在超时或失败提示中说明。
v0.2 吸顶：标题行随列表滚走，搜索、来源选择、分组栏和筛选范围组成的筛选栏固定在列表顶部（不透明背景），在万级频道的列表深处也能直接搜索或切换分组。实现上筛选栏是列表数据的首行并使用 stickyHeaderIndices，仍为单一虚拟化列表。
## 添加来源页
入口：频道页添加按钮、空状态、来源管理。两种方式切换：HTTP(S) 链接与系统文件选择。表单包含来源名称、地址或文件名，空名称可使用主机名或文件名。状态：编辑、校验错误、下载中、解析中、预览、保存中、成功、失败和用户取消。
预览显示有效条目、重复条目、忽略条目及原因摘要。没有有效频道时禁止保存；部分行损坏时必须先显示统计，让用户确认是否导入有效部分。返回或取消应取消任务，不能留下半套频道。
## 播放器页
入口：频道、收藏、最近。竖屏上部为视频，下部显示频道名、来源和收藏按钮；全屏只保留必要控件。状态：准备、缓冲、播放、暂停、失败、已结束。直播不显示虚假的总时长，不承诺可拖动回看。
轻触显示或隐藏控件；全屏按钮明确标记。返回键先关闭频道面板，再退出全屏，最后返回原列表。失败提示说明类别，给“重试”和“返回频道”；不要只显示原始异常栈。视频默认等比适配，允许黑边，不默认裁切内容。
## 收藏和最近
入口：底部导航、播放器收藏操作。收藏为空提供返回频道的入口；失效频道显示“来源已不再提供”，不偷偷跳到同名频道。最近按最后成功开始播放的时间排序，上限 100 条，同一频道更新原记录。
## 设置和来源管理
设置提供来源管理、移动网络提醒、清空最近、清空本地数据、版本与隐私说明。来源管理显示最近成功刷新时间、状态和频道数，提供添加、刷新、改名、删除。清空最近、删除来源和清空全部数据都要二次确认，并说明不可在应用内撤销。

v0.2 手动可用性检测：来源管理中每个来源提供“检测可用性”，只在用户点击时运行，需已获联网许可并通过计费网络确认；对该来源的有效频道逐个发送 Range 0-1023 请求（8 秒超时，最多 4 个并发），进度可见、可随时停止，停止时保存已完成的结果；切到后台、撤销许可、删除来源或清空资料时自动停止，撤销许可后不保存旧许可下的结果。结果仅表示服务器有成功响应，不代表能解码播放；刷新后地址变化的频道清除旧结果。这与“导入阶段不逐个探测”不冲突：检测是用户主动发起的独立操作。
# 3 技术架构和工程结构

## 推荐技术栈
使用 React Native 与 TypeScript，采用稳定 Expo SDK 配套的 development build。它是包含本项目原生模块和配置的开发应用；Expo Go 可辅助早期观察，不能替代最终 APK、网络策略与三星设备验收。首版不开发 WebView 播放器，不自行实现解码内核。[1]
Expo Router 负责路由，React 组件与 StyleSheet 构建界面，expo-video 调用原生视频能力；expo-sqlite 保存频道与用户数据；expo-document-picker 选择文件，expo-file-system 读取系统选择器的缓存副本。v0.2 补齐配套模块：expo-network（联网与计费网络判定）、expo-screen-orientation（全屏方向）、expo-navigation-bar 与 expo-status-bar（沉浸式全屏）、expo-system-ui、react-native-safe-area-context（安全区）。Android 侧播放器由组件封装，不直接另建一套 Kotlin UI。[2][3]
用 npx expo install 安装与 SDK 匹配的 Expo 组件，提交 package-lock.json，固定 Node 与包管理器版本。开发前核对 Expo SDK、React Native、React、播放器及 Android 工具链的兼容矩阵；不混用 beta 播放器或动态依赖版本。保留一份可干净构建的基线。
## 状态管理和边界
先用 React 状态和按功能封装的 hooks；确需跨页面共享播放会话与筛选时才用一个小型 Zustand store。它只保存临时 UI 状态，不与 SQLite 双写整套频道。数据库是持久数据的唯一事实来源，仓库查询结果更新界面。
UI 调用用例或 repository，不直接拼 SQL。领域层包含类型、解析规则、身份匹配与错误分类；数据层包含 SQLite、文件和下载适配；PlaybackController 封装 expo-video 的命令与事件。测试可替换这些边界，无需后端 API 或微服务。
状态使用 TypeScript 判别联合表达加载、成功、空与失败。取消标志、会话 ID 和请求代次贯穿异步流程；组件卸载时清理监听器与计时器。重要业务规则不塞进页面 useEffect。
## 建议目录
app/  Expo Router 路由，保持薄页面
src/features/source/  添加、刷新、来源管理
src/features/channel/  列表、搜索、收藏、最近
src/features/player/  播放页面和控制面板
src/domain/  类型、M3U 解析、身份及错误规则
src/data/  SQLite 仓库、迁移、文件和下载
src/playback/  expo-video 适配器与会话状态
src/components/ 与 src/theme/  通用交互与样式

plugins/  必需的 Android 配置插件
__tests__/、e2e/、fixtures/ 与 docs/  测试及说明
## 原生配置和权限
用 app.config.ts 与 config plugins 管理 Android 网络安全、备份和权限，避免修改后被 prebuild 覆盖。原生目录采用可再生成策略；如后续手工维护，必须明确切换工作方式。需要原生扩展时先说明理由，不把它作为首版默认复杂度。
仅保留网络与必要状态权限，使用系统文件选择器，不索取全盘存储、位置、摄像头或麦克风。明确关闭后台播放、画中画和不需要的服务。首版不含广告、统计、推送、登录或云更新服务依赖。

# 4 本地数据和稳定标识

## SQLite 数据模型
Source：id 为 UUID；name；kind 为 URL 或 FILE；location 为地址或原文件名；content 仅文件来源使用，保存文件原文于私有 SQLite（v0.2，替代单独的私有文件副本，刷新时重新解析）；createdAt；lastSuccessAt；lastErrorCategory；revision。地址可能含令牌，不能出现在普通列表和日志中。局域网地址仍不支持。
Channel：id 为 UUID；sourceId 外键；identityKey；name；groupName；tvgId 可空；logoUrl 可空；streamUrl；sortIndex；active；lastSeenRevision。对 sourceId 加索引，对 sourceId 与 identityKey 建唯一约束；名称索引用于本地查询，首版千条规模无需独立搜索引擎。v0.2：频道写入使用多行 INSERT 批量提交（每批 90 行、每行 10 个绑定参数，低于 SQLite 默认 999 上限），避免每个频道一次原生往返。
Favorite：channelId 主键与外键；createdAt。Recent：channelId 主键；lastPlayedAt。历史和收藏引用稳定 channelId，不使用列表下标、频道名称或临时播放器索引。所有时间存 UTC，界面按设备时区显示。
Settings 表：主题、移动网络提醒选择及非敏感展示偏好。Zustand 仅缓存当前 UI 状态，不持久化第二份频道。通过 expo-sqlite 仓库访问，所有变量用参数绑定；数据库迁移必须显式定义并测试，不能用破坏性迁移悄悄清空收藏。
## 同一频道如何识别
在同一来源内，优先使用经本次列表验证唯一且非空的 tvg-id；它不是天然唯一。若重复，则退回完整标准化 URL 的哈希作为身份键。标准化仅做协议和主机大小写、默认端口等安全处理，保留路径大小写、查询参数及顺序，不擅自去掉 token。
同一列表内完全相同身份合并为一条，采用首条合法记录并统计重复。不同来源即使同名也不自动合并。两个频道同名不同 URL 且无唯一 tvg-id 时视为不同频道，避免收藏错连。
URL 令牌更新且没有可靠 tvg-id 时，无法无损判断是否还是同一频道。此时创建新频道并把旧收藏标为失效，不用名称模糊匹配悄悄迁移；后续可以增加用户手动重新关联。
## 刷新时保留用户数据
下载和解析在临时暂存区完成。事务内按身份匹配保留已有 id，更新名称、分组和地址；新增条目新建 id；消失条目标记 inactive。被收藏或有最近记录的失效条目保留名称供用户理解；无引用的失效条目可清理。
当前播放保持进入时的不可变频道快照。刷新不会强行切换正在播的地址；下次选择频道使用新地址。用户删除正在播放的来源时必须先停止播放，再事务删除来源及其关联记录。
## 隐私存储
数据库和暂存文件位于应用私有目录。禁止将来源 URL、访问令牌、观看历史放进外部公共目录；关闭或排除这些数据的系统云备份。首版不提供自动同步。卸载会移除本地数据，用户应自行保留合法来源文件；应用不能承诺卸载后恢复。

# 5 M3U 导入和刷新实现

## 输入校验和资源上限
v0.2：URL 接受公网 HTTP 与 HTTPS，禁止 userinfo 用户名密码字段和非网络协议；局域网、本机与特殊用途地址明确拒绝。端口只拒绝敏感服务端口：WHATWG Fetch 标准的“bad port”列表（如 21、22、25、110、554、10080）加常见局域网与数据库服务端口（445、1900、2375、3306、3389、5353、5432、5900、6379、9200、11211）；81、82、85、98 等流媒体常用的非标准低端口放行（v0.2 修订：此前拒绝 80/443 以外全部低于 1024 的端口，会误拦 iptv-org 中文列表里 24 个实测可解码的 CCTV 频道）。任何联网（含 HTTPS）前须经过应用内知情许可，详见第 8 章。本地文件由 expo-document-picker 调用系统选择器，设置 copyToCacheDirectory 为 true 以便文件 API 读取；校验大小后复制到私有受限暂存区并清理缓存，不把 content URI 当普通路径。[5]
优先读取 UTF-8，可处理 UTF-8 BOM、CRLF、LF、空行和中文名称。非法编码给出可理解错误，不静默生成乱码。v0.2 上限：输入 8 MiB（按实际字节计数，下载与文件读取一致，单一常量）、单行 64 KiB、条目 20,000 条。曾设为 2 MiB，但 iptv-org 完整列表 index.m3u 为 2.46 MiB、11,356 条，会被整体拒绝；8 MiB 留有余量且仍有边界。每项可调整但必须有边界。网络 Content-Length 只作参考，读取时实际计数。
## 解析规则
验证 #EXTM3U，解析 #EXTINF 属性和逗号后的名称，并关联下一条合法媒体 URL。支持 tvg-id、tvg-name、tvg-logo、group-title、tvg-country/country、tvg-language/language；无分组归入“未分组”，无可用名称时使用安全占位名。属性解析器必须处理引号与名称里的逗号，不能简单用 split(",") 拆整行。
忽略空行和未知注释，记录行号及错误类别。悬空 EXTINF、非法 URL、超长行计为无效条目。v0.2：HTTP 条目可以导入，预览单独显示 HTTP 频道数量，不改写成 HTTPS；文件列表内相对 URL 首版拒绝，网络列表可按最终列表 URL 解析相对引用，再执行同一安全检查。
列表如果包含定义 HLS 清单结构的标记（TARGETDURATION、MEDIA-SEQUENCE、DISCONTINUITY-SEQUENCE、STREAM-INF、I-FRAME-STREAM-INF、MEDIA、KEY、MAP、BYTERANGE、PLAYLIST-TYPE、ENDLIST、PART-INF、PART、SERVER-CONTROL），按 HLS 播放清单识别，提示“这是播放地址，不是频道目录”；不可把分片当成频道。v0.2：其他 #EXT-X-* 行（如 VERSION）按未知注释忽略，避免手工拼接的频道目录整体被拒。首版通过频道目录导入 HLS 地址，不额外增加直接播放地址页面。v0.2：刷新同样需要预览并确认后提交。
## 流式处理与确认
网络下载与文件读取优先使用所选 Expo 版本支持的有界分块接口，记录实际字节数。TypeScript 解析器分批处理并主动让出 JS 执行时间，不能用一个同步循环阻塞界面；若接口只能整体读入，则进一步收紧文件上限并先测内存，不虚称流式。达到任一上限立即终止并删除暂存数据。只统计解析结果，不自动请求所有 logo 或频道地址；首版频道 logo 使用本地图标占位。
有效条目为零时整体失败；存在有效条目和坏行时显示预览，用户确认后提交。刷新为零有效条目时始终失败并保留旧数据，不提供确认清空；非零但存在坏行时需明确确认。下载失败、取消或磁盘不足都保留旧版本。
## 事务和并发
同一 sourceId 的提交串行化，每次任务携带 generation 和源 revision；只有最新仍有效任务能提交。重复点击刷新合并为一个任务。删除来源后旧任务即使返回，也不能重新插入数据；事务提交前检查来源存在及 generation。
导入任务取消时关闭输入流和 HTTP 调用，清理临时文件。参数化 SQL 的每批插入暂存区应有上限，最终用 SQLite 独占事务或已验证的串行事务队列更新正式数据；崩溃重启清理孤立暂存批次。文件来源刷新使用私有保存副本，替换内容通过重新选择文件，避免依赖失效的长期 URI 权限。

# 6 播放状态和生命周期

## 播放器适配层
PlaybackController 提供 selectChannel、play、pause、retry、stop 与只读状态。使用 expo-video 的 VideoView 和 useVideoPlayer，由原生组件承担解码，不用 JavaScript 手写媒体管线。封装组件版本相关 API，业务页面不散落播放器底层调用。[2]
组件事件转换为应用状态：Idle、Preparing、Buffering、Playing、Paused、Error、Ended。状态附带 channelId、sessionId、播放意图、错误类别和重试次数。播放器属性变化并不等于 React 重新渲染，应订阅状态与播放事件，并在卸载时清理订阅。[2]
## 换台与旧事件
每次选台或重试递增 attemptId，取消旧计时器与网络检查。空构造的 ExoPlayer 会立即报告播放结束，因此只有本次尝试已真正开始播放后才接受“已结束”事件（v0.2 模拟器实测发现）。v0.2 实现：每次播放尝试新建一个空 expo-video 实例，先订阅事件再附加来源，换台、重试、暂停或离开时释放旧实例，旧实例的晚到事件按 attemptId 丢弃；以多一次解码器初始化为代价换取会话彻底隔离。A、B、C 连续点击时，晚到的 A 事件不能覆盖 C 的状态。换台耗时须在真机测量，若明显慢于预期再评估复用单实例加 latest-wins 替换。
只有当前会话已准备且确认开始播放才更新最近观看。界面显示“正在切换至某频道”，清理旧错误；频道面板选中项与实际当前会话一致。切换失败停留当前目标并提供重试，不偷偷返回另一个频道。
播放前格式判定（v0.2）：Android 上 expo-video 的 auto 不传 MIME，ExoPlayer 只按网址后缀推断，无后缀的 HLS 会被当作普通文件而失败。因此：.m3u8 设为 hls，.mpd 设为 dash，常见媒体文件后缀（mp4、ts、flv 等）交给 auto；其余地址在当前播放尝试内先发一次 Range 0-1023 请求，最多读取 1 KiB、8 秒预算，响应头 Content-Type 含 mpegurl 或 dash+xml 时直接采用，否则按内容开头 #EXTM3U 判为 hls、<MPD 判为 dash。探测失败、HTTP 错误或无法识别一律回落 auto，由播放器报告真实错误；换台、暂停或离开时探测随尝试一起取消；探测只在已获联网许可且通过计费网络确认后进行，不记录地址。识别或播放失败统一按未确定原因处理。HLS 容器支持不等于设备能解码其中全部编码。[2]
## 全屏与旋转
任何时刻只挂载一个播放器实例和一个 VideoView（TextureView，便于叠加控件），避免重复音频或 Surface 问题。首版采用应用内全屏布局，结合安全区域和屏幕方向控制，保留自定义频道面板；不要先承诺原生全屏容器可任意叠加 React 控件。
旋转只改变布局，不重新创建播放器。v0.2 方向策略：播放页竖屏时锁定竖屏，通过“横屏全屏”按钮进入全屏并锁定横屏（两个横向均可），避免握持晃动误触发；离开播放页恢复进入前的方向策略。全屏时隐藏状态栏与导航栏（沉浸式，边缘滑动可临时唤出）；轻触画面显示或隐藏控件，正在播放且无频道面板时 4 秒后自动隐藏，非播放状态（连接、错误、暂停）始终显示控件；开启 TalkBack 时不自动隐藏。进入或退出全屏时控件重新显示。v0.2 换台：全屏画面上下滑动换台（默认上滑下一台，设置“换台反转”可对调），到首尾时提示“已经是第一个／最后一个频道”而不循环；TalkBack 用调节手势的增减动作换台。全屏到达新频道时顶部短暂显示“序号/总数 · 台名”。控件显隐状态跨频道保留，连续滑动换台时控件保持隐藏；加载中不再强制显示控件，错误、超时、暂停等需要决定的状态仍会显示。播放器提供“回上个台／↩ 回到 …”一键返回上一个观看的频道。设置“跳过不可达频道”（默认开）时，上一台、下一台和滑动跳过上次可用性检测为不可达的频道。返回顺序是关闭频道面板、退出全屏、返回原列表。键盘、系统返回和横屏都不应丢失筛选或当前选择。
## 页面焦点和系统生命周期
用路由焦点与 React Native AppState 共同判断是否允许播放，不能仅依赖组件卸载，因为离开页面可能仍保留路由组件。失去页面焦点、应用进入后台或锁屏时暂停；不启用后台播放和前台媒体服务。停止不必要的缓冲，必要时清空 source，回来后由用户重新开始。
useVideoPlayer 的资源生命周期与组件绑定；手动创建实例时自行 release。一个播放器只绑定一个明确所有者，避免重复释放。进程被杀后恢复频道数据和页面选择，不自动播放；直播继续时从当前直播点开始。
## 音频与屏幕策略
按照 expo-video 的实际音频混合与中断能力配置为尊重其他媒体；来电、音频焦点丢失、耳机拔出和蓝牙断连必须在三星真机检查。不得假设所有事件都已暴露给 JS；若标准组件无法达到暂停要求，先记录阻塞并评估最小原生扩展，不声称纯 JS 已解决。
仅在前台、播放器页可见且播放或短暂缓冲时保持常亮，暂停和退出时释放。音量交给系统按键，不加亮度或音量滑动手势；默认等比显示，不裁掉画面。首版不做后台音频、画中画或自动抢回音频焦点。

# 7 网络错误和三星手机适配

## 错误分类和呈现
目录下载可按实际 HTTP status 分类。expo-video 的播放错误接口未保证提供结构化 HTTP 或解码错误码，因此下面细分只适用于冻结版本可靠暴露的信息；其余统一显示“播放失败，原因未确定”。不靠脆弱字符串匹配或预请求伪造原生错误码，未知错误只允许手动重试。
没有网络：提示检查连接，保留频道，不无限重试。v0.2：只有系统报告未连接（isConnected=false 或类型 NONE）才判定离线；isInternetReachable=false 只说明系统联网验证（Google connectivitycheck）不通，在中国大陆等网络常见而实际可上网，此时照常发起请求，由真实请求结果决定。DNS、连接超时或短暂 5xx：提示网络或来源暂不可用，可有限重试。401/403：提示来源授权、有效期或地区可能受限，不能断言一定是哪一种。404/410：提示地址失效，建议刷新来源。
TLS 证书错误：停止并提示安全连接失败，不绕过验证。解码器初始化或不支持格式：提示设备或当前播放器不支持该格式。解析错误：区分“频道目录格式错误”和“直播流无法解析”。不在错误页暴露完整 URL、令牌或异常堆栈。
判断客户端问题需要有对照：同一受控样本、同一网络和设备可重复失败，结合本地错误码排查。公网频道打不开不能直接归咎于应用，也不能把所有失败都说成节目源失效；测试报告记录证据和未确定项。
## 超时和重试建议值
导入连接超时 10 秒、单次读取停滞 15 秒、整次导入总预算 60 秒。播放首帧等待目标 15 秒后显示提示并允许取消，最终失败预算初设 30 秒，按受控网络测试调整。持续直播不设置整场播放 60 秒总超时。
v0.2：连接中显示已等待秒数；满 15 秒提示“比平时慢，节目源可能已失效”，全屏且控件隐藏时同时给出“换下一台”（其他情况下屏幕上已有下一台按钮，不重复）。冻结版本的 expo-video 只提供非结构化错误消息，无法可靠判定瞬时故障，因此播放端不做应用层自动重试，所有播放失败只允许手动重试；首次连接等待 30 秒后显示超时。expo-video 原生层可能有内部加载重试，不能宣称 JS 已精确控制底层分片请求次数。手动重试开启新会话，清楚显示当前状态。目录下载仍按 HTTP 状态分类。
切换频道、离开播放器、取消导入和删除来源均应取消相关请求。网络从 Wi-Fi 切到移动数据时遵守提醒设置，默认暂停并询问；首次移动网络播放告知可能消耗较多流量。网络恢复后不在后台自行播放。v0.2 统一判定：导入与播放使用同一规则，Wi-Fi、以太网、蓝牙视为非计费，蜂窝、VPN 和未知网络视为可能计费；用户确认一次后，在连回 Wi-Fi 之前导入和换台不再重复询问，连回 Wi-Fi 后确认失效，再切到移动数据重新询问；清空全部资料同时清除该确认。
## Galaxy S25 Ultra 界面要求
使用 React Native 逻辑尺寸、弹性布局和系统字体缩放，不以具体物理像素写死布局。适配 edge-to-edge、状态栏、导航栏、摄像头开孔和横屏安全区域；全屏视频可延伸到屏幕边缘，按钮必须留在安全区域内。手势导航及三键导航分别检查。
检查系统字体 100%、130% 和最大常用档位，频道名可换行或省略但核心按钮不得消失。触摸目标至少 48 dp，收藏按钮提供可访问性标签；深色主题确保文本与背景清晰，TalkBack 可读出频道名及收藏状态。
## 兼容性验证边界
记录真实 Android 和 One UI 版本，测试竖横屏、反复旋转、分屏缩放、锁屏、来电、耳机断连和省电模式。处理返回手势和系统方向锁定；手动全屏退出后恢复原方向策略。通过这台手机不代表所有三星手机都通过，模拟器也不能代替真实解码与耗电测试。

# 8 安全边界和隐私设计

## HTTP 与应用内知情许可（v0.2 修订）
v0.1 的 HTTPS-only 决定已撤销。原因：中文直播源中 HTTP 地址占比很高，且 HTTPS 主清单也可能引用 HTTP 子清单、分片、密钥或重定向；HTTPS-only 会让大量常看频道无法播放，与“自己每天用着舒服”的首要目标冲突。
v0.2 做法：打包时开启平台明文能力（usesCleartextTraffic=true，由 config plugin 写入）；任何联网（包括 HTTPS 目录下载和播放）前弹出一次风险说明并取得明确同意，拒绝则不下载、不创建播放器来源；设置中可随时撤销，撤销会取消进行中的导入并释放播放器。HTTPS 不关闭证书或主机名验证，不存在信任全部证书的代码。
边界：Android network security config 是打包时配置，不是运行时授权表；expo-video 原生 HLS 请求不经过 JS，应用无法逐层拦截子清单、分片、密钥或重定向。因此本能力只适用于个人自用、用户信任的来源，不得用于自动接受陌生列表的公开分发；公开推广前须重新评估是否改回 HTTPS-only 或实现原生全链路网络门禁。[4]
## 不可信节目单与本机网络
虽然没有服务器，恶意列表仍可能诱导手机访问路由器、内网设备或本机服务，这是客户端的非预期网络访问风险。入口校验拒绝显式 loopback、私网、链路本地、组播等地址；首版不提供局域网开关；确有需求时再设计受限范围的独立授权。
v0.2 限个人自用、由用户明确选择并信任的 HTTP(S) 来源。导入前说明：目录、播放服务器及其重定向可能接收到 IP 地址和访问请求；不应导入陌生人发送的未知列表。JS 层拒绝显式本机或私网 IP、异常端口和危险 scheme，但这只是基础输入校验。
现成 expo-video 的原生 HLS 请求不一定经过 JS fetch。不能把顶层 URL 校验说成能阻断全部子清单、分片、密钥、重定向和 DNS 重绑定。首版不承诺完整内网隔离；它是可信来源条件下仍需知晓的残余风险。若要接受未知第三方列表或公开推广，需先研究并实现原生全链路网络适配，再单独安全验收。
默认不支持自定义 Cookie、Authorization 或 Referer，不主动向其他主机附加认证信息。URL 中自带令牌及服务端重定向由可信源规则约束，无法宣称客户端能完全控制服务端行为。拒绝 file、javascript、intent、data 等 scheme，远程台标默认关闭；用户分别允许节目来源联网和台标访问后，才加载经过校验的 HTTPS 台标主地址，原生重定向不能由 JS 完全隔离。
## 日志与备份
日志仅保留内部来源 ID、频道 ID、错误类别、HTTP 状态和耗时，不打印查询参数、请求头、完整 URL、M3U 原文或观看记录。release 关闭详细日志；错误报告由用户查看后主动分享，首版无遥测、分析和自动崩溃上传。
源地址可能包含访问令牌，设置页默认只展示名称和主机。若需要复制地址，由用户明确操作，不自动复制到剪贴板。数据库、来源副本及日志排除系统备份。v0.2 明确实现：allowBackup=false 只覆盖 Android 11 及以下与云备份；Android 12 起（targetSdk ≥ 31）设备间迁移（如三星 Smart Switch）只看 dataExtractionRules，因此 config plugin 同时写入 dataExtractionRules（cloud-backup 与 device-transfer 均排除全部数据域，含 device_* 域）和 fullBackupContent（Android 11 及以下）。仍须在三星真机用 Smart Switch 验证。
## 文件和数据删除
系统文件选择器只授予选定文件的读取能力。首版将内容复制到私有目录并关闭流，不持久化外部 URI 权限；如果未来改为保留 URI，必须处理权限撤回、文件移动和提供者离线。[5]
清空全部数据先确认，然后停止播放器和任务、删除数据库及私有源文件、重置设置。错误路径不应留下令牌文件。删除后冷启动应回到空状态；用户自己的原始文件不应被删除。
## 许可和分发
记录直接与传递依赖许可，交付第三方声明。开源客户端许可和频道内容使用权分别核对；不把开源许可当作广播授权。个人 APK 安装不要求先上应用商店，但也不能据此忽略内容或所在地规则。

# 9 功能验收用例

以下用例逐项记录通过、失败或待测，并附设备、系统版本、构建号和样本编号。固定夹具用于稳定复现，外部直播仅作补充。实际执行前不能填写“通过”。
## 导入与列表
01 合法 HTTPS M3U：导入 10 个样本频道，名称、分组、地址和统计一致。
02 本地文件：系统选择器导入后重启应用，列表仍存在；原文件不被修改。
03 中文与换行：UTF-8 BOM、中文名称、CRLF 和 LF 得到相同结果。
04 属性边界：带引号属性、名称内逗号和空 group-title 正确处理。
05 无效输入：空文件、HTML、缺少头部和损坏编码提示错误，保留表单输入，不写正式数据。
06 部分坏行：显示有效与无效数量；取消不保存，确认只导入合法条目。
07 资源上限：超大文件、超长行、超量频道及时停止，不发生 OOM 或界面无响应。
08 HLS 误导入：媒体或主播放清单不被拆成分片频道，给出正确提示。
09 重复和同名：完全重复合并；同名不同地址不错误合并；重复 tvg-id 不碰撞。
10 搜索筛选：分组、来源和中文搜索组合生效；无结果可清空；退出播放保留滚动位置；在“收藏、频道、最近”之间切换后各自恢复原滚动位置（v0.2）。
## 数据一致性
11 收藏持久化：收藏后杀进程重启仍存在，取消收藏不删除频道。
12 最近记录：成功播放才入列，同一频道不重复，超过 100 条淘汰最旧条目。
13 刷新保留：可靠身份相同但 URL 更新时，channelId、收藏和历史关联保留。
14 刷新失败：断网、坏格式、取消或存储失败均保留旧频道，显示最后成功时间。
15 失效频道：刷新移除已收藏频道后，收藏显示失效，不跳到同名其他频道。
16 并发刷新：连续点击与慢旧请求不能覆盖较新结果；没有重复频道。
17 删除竞争：刷新未结束时确认删除，旧请求回来也不能复活来源。
18 删除确认：取消删除无变化；确认删除说明并落实关联收藏及历史影响。
## 播放基本行为
19 可控 HLS：授权样本可播放、暂停和继续；画面比例正确，无应用广告。
20 快速换台：连续选择 A、B、C，最终只播放 C；旧错误不覆盖 C 状态。
21 直播暂停：暂停不伪装成可无限回看；继续时回到直播位置。
22 格式差异：可支持格式成功；不支持编码显示解释，应用不崩溃。无 .m3u8 后缀的 HLS 地址（如 iptv-org 中 cdn.qd.je/163189/ch8）能正常起播（v0.2）。
23 观看交互：上一台、下一台与列表选台顺手，当前频道明确；返回先退全屏再回原列表，反复进入无双音轨或泄漏。
23b 换台（v0.2 新增）：全屏上滑下一台、下滑上一台，换台反转后对调；首尾提示不循环；台名浮层；回上个台；跳过不可达频道开关生效；连接满 15 秒出现慢源提示。
23c 吸顶（v0.2 新增）：频道页滚到列表深处，筛选栏仍在顶部可搜索、切换分组和来源。
23a 全屏控件（v0.2 新增）：全屏隐藏状态栏与导航栏；轻触画面显隐控件，播放中 4 秒自动隐藏，连接或错误时控件常驻，TalkBack 开启时不自动隐藏。

# 10 稳定性安全和性能验收

## 网络与生命周期
24 断网恢复：缓冲后给出可解释错误，不自动重试、需手动重试（v0.2）；取消后没有继续请求。
25 错误能力：目录 HTTP 401、403、404、500 正确分类；播放端只分类可靠暴露的信息，未知错误明确未确定、仅手动重试，不泄露令牌。
26 旋转：S25 Ultra 播放时往返旋转 10 次，无崩溃、双音轨、标题错位和重复导入。
27 后台锁屏：按 Home 或锁屏暂停，回到应用不擅自播放；退出后释放资源。
28 音频焦点：来电、其他媒体抢占、耳机拔出和蓝牙断开时按规则暂停。
29 进程重建：系统杀进程后恢复数据但不自动播放；没有残留临时导入。
30 网络切换：Wi-Fi 切移动数据遵守提醒和暂停策略，无后台自动续播；确认一次后换台不再重复询问，连回 Wi-Fi 再切回移动数据时重新询问；VPN 下按可能计费处理。
## 安全与三星界面
31 明文与许可（v0.2 修订）：未同意联网许可时，HTTP 与 HTTPS 目录均不下载、播放器不加载来源；同意后 HTTP 目录与 HTTP HLS（含 HTTPS 主清单引用 HTTP 分片）可播放；撤销后进行中的导入取消、播放器释放，抓包确认不再有请求。
32 TLS 失败：无效证书或主机名不匹配被阻止，没有信任全部证书代码。
33 来源边界：显式私网或本机地址被入口校验拒绝；用户能看到可信来源提醒及全链路 DNS 防护未覆盖的说明，不伪报完整隔离。
33a 备份与迁移（v0.2 新增）：解析 release APK 的 AndroidManifest 确认 allowBackup=false、dataExtractionRules 与 fullBackupContent 指向排除全部数据域的规则；三星 Smart Switch 换机后新机上无来源、收藏和观看记录。
34 文件边界：权限拒绝、文件消失或内容超过上限时可恢复，不索取全盘权限。
35 日志脱敏：含测试 token 的地址故意失败后，日志、普通列表、错误提示和备份中不出现 token；用户主动输入或明确查看地址的界面除外。
36 三星布局：横竖屏、开孔、两类系统导航和分屏下按钮可触达；常用操作适合单手，收藏与最近一键可达。
37 字体与辅助功能：放大字号不遮挡操作；TalkBack 能读出频道和收藏状态。
38 清空数据：确认后重启为空状态，原始选中文件仍在，后台没有继续拉流。
39 无广告与隐私：依赖清单无广告和统计 SDK；空启动不访问分析服务，不默认加载远程列表或台标。
## 性能目标与测量方式
以下是待验证的工程目标，不是已测成绩。S25 Ultra、release 构建、相同测试夹具与网络条件下记录基线，并保留无法达标的原因。调试构建数据不能代替最终结果。
1,000 条本地频道：冷启动到可操作列表目标不超过 2 秒；搜索稳定结果目标不超过 300 毫秒，其中约 250 毫秒输入防抖单独记录；本地 M3U 解析提交目标不超过 2 秒。使用至少 10 次测量报告中位数和 P95，不只挑最快一次。
受控 Wi-Fi 和受控公网 HTTPS 上的授权 HLS 固定素材：首帧目标不超过 3 秒，公网首帧单列观察不作保证。列表连续滚动应无明显卡顿，使用 release 构建帧时间工具记录，避免仅凭手感宣称 60 fps。
连续播放 60 分钟并换台 30 次：无崩溃、ANR 和持续增长的播放器实例；记录内存趋势、耗电及温度。合理缓存波动不算泄漏，停止后不能继续增长。真机未连接时，这组项目保持待测。

## 每次修改之后必须跑测试
每一个任务提交都附变更范围、实际执行命令、结果和未执行原因。项目建立并固定 npm scripts：typecheck 运行 tsc --noEmit，lint 运行 ESLint，test 运行 jest-expo 与 React Native Testing Library。以固定版本说明核对 Jest 与 RNTL 的组合，不能假设旧测试库兼容新 SDK。每次变更运行 npm run typecheck、npm run lint、npm test -- --runInBand；构建检查使用已生成 Android 工程的 ./gradlew assembleDebug。涉及 UI、数据库、旋转和播放时，追加真实 APK 上的 Maestro 冒烟与手工设备用例。
编译通过不等于测试通过。失败先定位与当前变更的关系，修复后重跑对应测试，再跑关键回归。没有运行条件时写“未执行及原因”，不得以预计通过替代结果，也不得为了绿灯删除断言或跳过失败测试。
建议按独立提交拆分：工程骨架、解析器、数据库、导入事务、列表收藏、播放控制、生命周期、网络安全、设备修复、发布。用本地 Expo development build 开发，最终 release APK 不依赖 Metro；不要求购买 EAS 服务。每次提交应可构建；先完成一条可演示流程再扩功能。

|---|---|---|---|

## 2026-10-18 三维分类与地区推荐

国别、语言、内容并列为三个下拉菜单，各自提供全部和未标注；收藏和最近仅保留搜索，避免重复功能。内容延续分组的多标签和中文化。台标是频道标识，不是正在播出节目的封面。
