# 静看 1.0 发布与验收

本仓库面向个人 Android 手机使用。正式候选配置：`com.jingkan.personal`，版本 `1.0.0`，versionCode `2`，arm64-v8a（Galaxy S25 Ultra）。后续覆盖更新保持包名、签名不变，并递增 versionCode。

## 生成发行文件

环境：Node >=24.13.0、项目锁定的 npm 依赖、JDK 21、Android SDK/NDK。设置 ANDROID_HOME。先运行 `npm ci`。

密钥由设备所有者亲自创建和备份：

```sh
./scripts/create-release-keystore.sh
```

脚本交互读取密码，将密钥保存在仓库外，Gradle 配置权限为 600。不要将密钥、密码或 gradle.properties 发到聊天、提交 Git 或放进发行目录。建议将密钥及密码分开保存在可靠的离线备份中。

审阅并提交代码后，在干净工作区运行：

```sh
npm run release:check
npm run release:build
```

打包入口依次运行类型检查、Lint、全部测试、JS bundle、Expo prebuild、Android release 构建。正式模式强制要求 release key，随后对发行副本检查包名、版本、arm64 架构、不可调试、权限、备份策略、签名和 16 KB ZIP 对齐，拒绝 Debug 证书。每次生成独立目录，避免后续构建覆盖已验证文件。

无正式密钥时可运行 `npm run release:test`。此模式明确标记为测试候选；默认可能使用 Debug 签名。测试包与正式包签名不同，不能直接覆盖升级。

输出保存在忽略的 `release/版本-构建号-模式-提交-时间/`，包含 APK、BUILD.json、SHA256SUMS、SIGNATURE.txt、THIRD_PARTY_NOTICES.txt 和本安装说明。只分发该目录内的文件，不分发整个工作区、数据库、真实节目源、node_modules 或签名配置。开源说明包括锁定依赖的许可证文本；如要公开分发，再针对 Android 原生传递依赖核对完整版权声明。

若构建被意外终止，先确认没有发布脚本运行，再移除 `.expo/jingkan-release.lock`。该锁阻止通过同一入口并发构建；不要同时手动启动 Gradle/prebuild。

## 从测试版切换

1. 在旧版中“设置 → 导出备份”，把未加密 JSON 保存到自己的安全目录。旧版没有备份功能时，先安装同一 Debug 签名的新版测试候选，确认原资料保留，再导出。
2. 核对 APK 的 SIGNATURE.txt 和 SHA256SUMS。若签名与旧版不同，Android 会拒绝覆盖；卸载前必须确认备份文件已成功保存。
3. 安装正式 APK，进入设置恢复备份。恢复会替换节目源、收藏和播放偏好，清空观看记录并重置所有联网、台标、IP 和定位许可；不会立即刷新或播放。备份最大 32 MiB，格式/关联数据校验失败不会替换数据库，写入失败事务回滚。
4. 从应用内重新阅读联网说明并授权，导入自己有权观看的来源。

应用禁用系统自动备份和换机迁移。手动导出文件内含完整地址和令牌，请勿公开分享。观看记录不在手动备份中。
